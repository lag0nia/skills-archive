# Unknown Historical Execution Lineage

Use this route only when real historical execution evidence exists but its exact workpack/snapshot association cannot be established. Missing association is neither proof of no implementation nor permission to certify a guessed workpack.

1. First search recoverable workpack history, execution summaries, implementation reports, and receipts for a genuine matching association. Report the records inspected and the precise uncertainty. A hash computed from today's workpack does not establish which content ran historically.
2. Before applying recovery to a consumer project, obtain explicit user authorization for this legacy-lineage recovery route. General implementation or release authorization is insufficient. Adding this policy to a skill is not authorization to apply it to a project.
3. Preserve old workpacks and execution evidence byte-for-byte in recoverable history before changing the stable workpack. Link that history from the existing workpack's starting-baseline explanation and later execution summary; do not create a parallel registry or fabricate an old receipt. Record `Historical workpack association: Unknown` with the missing scope/coverage stated explicitly.
4. Inspect the current implementation and establish its actual baseline, identifying real implemented behavior, current source/revision, available observations, and requirements whose prior verification cannot be established. Keep historical execution claims separate from fresh observations.
5. Require the ordinary current approved Stage 9 handoff, readiness validation, planning reconciliation, scope, prerequisites, protected boundaries, and evidence requirements. Failure still forbids planning. The route replaces only the impossible historical matching-receipt prerequisite, never current readiness or acceptance gates.
6. Prepare one current-scope workpack for the necessary implementation delta plus fresh verification of requirements whose prior coverage is unknown. Do not reimplement working behavior solely to repair paperwork; a verification-only scope is legitimate when current inspection establishes no implementation delta, but it must execute real required checks. Retain all ordinary planning requirements and the unknown historical association.
7. Start and successfully execute that exact current workpack, recording its content identity at start in the existing summary. Issue a new implementation receipt only after all its acceptance and verification requirements pass. Never retroactively certify the old workpack, relabel its evidence, or imply that the new receipt proves its historical execution.

If a genuine matching receipt is recovered, use the ordinary lineage/classification path. If current readiness fails or authorization is absent, preserve the records and report the blocker; do not overwrite the stable workpack or bypass validation.
