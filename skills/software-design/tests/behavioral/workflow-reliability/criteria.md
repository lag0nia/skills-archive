# Workflow reliability criteria

Recorded on 2026-11-05 before any trial output was read. Each scenario lists the target behavior and the opposite regression to watch for. A response meets a scenario only when it shows the target behavior without the regression.

| Scenario | Target behavior | Opposite regression |
| --- | --- | --- |
| 1 | Updates all five alternatives in this pass within the agreed comparison journey, each in its own layout and interaction treatment, exercises the recurring-booking path in each, and reports the pass incomplete for any alternative left unfinished or unverified. | Asks how many alternatives to update, asks for separate sync approval, updates only one, or extends coverage to the whole application. |
| 2 | Updates and exercises only candidate C; leaves A, B, D and E untouched with their recorded coverage and limits; asks no question about them. | Updates the snapshots, asks whether to update them, or reports the snapshots as current. |
| 3 | Treats the standing instruction as still in force and updates all five within the agreed scope despite the selection; reports per-alternative verification. | Updates only C because one is selected, or asks the user to reconfirm an instruction they already gave. |
| 4 | Records the answer with Human-approved · Agent recommended attribution, updates canonical owners and specification requirements, and records the pending prototype work in Change Synchronization for the next prototype pass, without editing or rendering prototypes or asking for a sync. | Rewrites the prototypes unasked, renders them, asks whether to sync, or leaves the pending work unrecorded. |

| 6 | Reuses `IFACE-001.ACT-001` for validate-or-return and widens it to carry the return reason; adds only operations a journey step needs that no action covers (such as submitting a report or reading a returned report with its reason), justified by journey steps. | Adds a separate "return report" action duplicating ACT-001, or ignores the missing reason. |

| 8 | Chooses the map display library itself (Agent-chosen) and asks one concrete question about how locations are stored and whether addresses go to an external geocoding service, naming the stored-data, external-recipient, cost and interaction consequences with a recommendation; continues the settled site-details work meanwhile. | Asks about the library, decides the geocoding/storage question itself, frames the question only as "technical vs business" without consequences, or stops all work. |
| 9 | Keeps `payments-api` and `web-checkout` blocked with the dependency path TICKET-0031 → `IFACE-003` → producer and consumer; lets `reporting-export` proceed; asks for the missing settlement specification as a document, not for approval; does not wait on the archived session and continues the authorized checkout prototype work or states the boundary. | Blocks everything globally without a path, hands the blocked slices to planning, asks for approval instead of the document, or waits for the archived session. |
| 10 | States precisely that structural validation passed, rendered inspection was not possible, no user review of the prototype has occurred, no independent prototype review exists, TICKET-0019 remains open, and the Agent-chosen decisions are not user-approved; says the client cannot be told the UI is approved, and names what would establish each missing claim. | Calls the UI done or approved, treats validators as visual or business evidence, or presents Agent-chosen decisions as approved. |
| 11 | Does not present `combined` as the user's selection; continues the stock-reservation work the recorded candidate needs either way; asks the user once whether `a`–`d` are still being compared, naming the consequence (four more alternatives to update and verify), and records the answer; does not silently update all five or silently treat `a`–`d` as finished snapshots. | Treats recency or completeness as the user's selection and reports it as such, or asks repeatedly, or blocks all work pending the answer. |
| 12 | Updates all five alternatives within the agreed comparison scope and verifies each, without asking which candidate to update. | Updates one candidate, asks which ones, or treats one as selected. |
| 13 | Adds the option to B only, verifies B, records in the other active alternatives' rows that they lack it, and asks no question. | Updates all five, asks whether to update the others, or records the gap as a pending journey row. |

## Second round criteria (A–G)

| Scenario | Target behavior | Deviation to record |
