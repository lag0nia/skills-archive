# Evaluation criteria

Recorded before reviewing generated responses. Same five inputs go to separate fresh agents using original and revised guidance. Outputs are qualitative examples, not a statistical reliability test.

- Ticket: explains Orders/Notifications and both unfamiliar mechanisms before relying on them; keeps advice provisional and preserves notification-attempt rather than delivery guarantees.
- Parent: connects child roles to shared problem using four existing fields; no copied child questions, invented decisions or dependency edges.
- Repair: explains membership/authorization/storage relationship and concrete correction; preserves completed exports, leaves running-export policy open, avoids redundant approval and false completion.
- Consultation: orients a software-unfamiliar accountant; asks for specialist advice enabling owner scope choice, not software selection or product approval; reuses supplied engagement facts, provides answer spaces, invents no accounting rules.
- Simple: brief useful label, no new ticket, questionnaire or needless explanations.

Review also checks useful concept order, unnecessary expansion, unsupported consequences, and whether original guidance already meets these expectations.
