# UI/UX Module Reading Guide

This folder contains the portable design guidance and reusable starters used by Software Design. It uses settled product and system behavior as constraints and explicit hypotheses for questions that bounded prototype exploration can help answer and produces a concise presentation-and-interaction specification plus a selected interactive prototype, with optional bounded alternatives during direction exploration. It does not own product policy or system behavior.

Read selectively:

- Read [design-workflow.md](design-workflow.md) when establishing or reviewing an interface direction, comparing conversational text wireframes, or creating one or more bounded prototype directions.
- Read [examples.md](examples.md) only when a concrete contrast would help resolve a design question or when a draft relies on excessive explanation or a generic layout.
- Use [templates/specification.md](templates/specification.md) and [templates/prototype.html](templates/prototype.html) for the launcher and [templates/candidate.html](templates/candidate.html) for a candidate entrypoint only when creating the corresponding artifacts. The prototype starter demonstrates mechanics and is meant to be replaced, not visually inherited.
- Use [templates/slides.html](templates/slides.html) only when producing an opted-in, optional `alternatives/<candidate>/slides.html` review slideshow from real screenshots, following [Optional Review Slideshows](design-workflow.md#optional-review-slideshows). An unpopulated copy is not a deck.

The module is deliberately independent of Software Design stages, tickets, Build Units, and readiness terminology. [../ui-ux-design.md](../ui-ux-design.md) owns that integration.
